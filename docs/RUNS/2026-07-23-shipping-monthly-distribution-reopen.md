## 根因

1. 运费从整页拼接文本抽取，未支持 `运费￥10起/运费￥1.8起`，也没有字段级局部证据和来源记录。
2. 页面不同商品的运费节点位置变化时，固定位置或整页正则都不稳定。
3. 月代销正则不支持 `<10`；失败后容易留下空值或被其它近义指标误读。
4. 旧测试只有 `月代销1.2万/代发运费8元`正例，没有截图变体和干扰负例。
5. 运费“元起”只有下限，旧数值筛选会把起步价当成确定金额，可能错误通过最大运费条件。

## 修复

- 在主文档、开放 Shadow DOM 和最多 12 个 frame 中收集短、可见、带标签的局部候选，按短文本优先。
- 运费支持 `运费/快递费/代发运费 + ￥金额 + 起/以上/以内`及首重/续重表达。
- 排除“退货包运费、赠运费险、运费查询”等干扰；没有金额短证据时保持缺失/待核验。
- 月代销支持 `<10`、`80+`、`1.2万`、`100以内`等边界文本，且与月代发订单、近30天代发数量严格隔离。
- Node 返回字段级 `field_evidence`；Python RPA 适配层传递到服务，JSON 核验记录保存证据类型、文本、来源和 selector 提示。
- 数值筛选增加区间语义：`1.8元起`只知道下限，不能证明落在 1-5 元完整区间时返回待复核；多段首重/续重也不作为确定总金额比较。
- 工作台版本号更新为 `2026.07.23-shipping-monthly-metrics-r1`。

## 负例回归

1. `月成交<10 月代销<10 运费￥10起 退货包运费 运费查询`
   - `units_30d == "<10"`
   - `dropship_shipping_fee == "10元起"`
   - 月代销不得写入月代发订单。
2. `月成交2600+ 月代销80+ 近30天代发数量100以内 运费￥1.8起`
   - `units_30d == "80+"`
   - 不得被 `100以内` 覆盖。
   - 运费为 `1.8元起`。
3. 只有“退货包运费/运费查询/赠运费险/券后￥1.8起”时不得生成运费金额。
4. `1.8元起`面对 1-5 元筛选返回未知/待复核，不能假装确定通过。
5. Python 适配层和服务核验记录不得丢失 Node 字段证据。
