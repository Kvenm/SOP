# 2026-07-11 Web 任务类目隔离修复

## 现象

- 第一个任务选择 `配饰、鞋、箱包>围巾/防晒>防晒面纱面罩`。
- 第二个任务选择 `运动户外、玩具童装>山地野营>帐篷`。
- 帐篷任务结果中再次出现防晒面纱任务。

## 根因证据

本地快照确认不是结果表残留，而是第二次请求同时提交了两个类目：

- `20260711_162133_953`：仅防晒面纱，50 个候选。
- `20260711_163142_637`：请求 categories 同时包含防晒面纱和帐篷，后端按多类目任务分别采集，得到 100 个候选。

旧前端两种选择入口都直接对 `selectedCategories` 执行 `Set.add()`；选择新叶子类目不会替换上一次任务的类目。

## 修复

- 新增“多类目任务”开关，默认关闭。
- 默认单类目模式：选择新叶子类目时先清空旧类目，再加入当前类目。
- 只有显式开启多类目任务时才允许累计多个类目。
- 从多类目切回单类目时，确定性保留最后选择的类目。
- Web 请求新增 `multi_category_mode`；服务端在单类目模式下同时收敛：
  - `categories`
  - `library_filters.category_paths`
- 新任务正式发起前清空旧 rows、run_id、核验队列和下载链接，但保留当前筛选条件。
- `runBtn`、悬浮运行按钮和“读取当前页”使用统一 collecting guard，防止两个请求响应互相覆盖。
- 类目切换时保存并恢复高级筛选控件值，避免重建 DOM 后丢失筛选条件。

## 用户操作

- 刷新本地页面后，默认显示“单类目任务”。
- 先选防晒面纱、再选帐篷时，已选区应只剩帐篷。
- 如确实需要一次同时采集多个类目，先勾选“多类目任务”，再逐个选择。
