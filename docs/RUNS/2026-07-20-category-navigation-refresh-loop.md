# 2026-07-20 类目菜单不展开与首页刷新循环修复

## 用户反馈

- 开始筛选后无法选择类目。
- 1688 一直停留在主界面没有动作。
- 停留一段时间后自动刷新，随后持续重复刷新。

本问题按新 Bug 处理，并按 `docs/ISSUE_FIXING.md` 重新取证。

## 现场证据

- Windows 最近任务 `gEKuavryceWNi1SJ` 共 13 个类目，任务状态一直推进到“正在打开第 13/13 个类目页面”，没有形成正常结果。
- 多类目实现会为每个类目启动独立 RPA；每个 RPA 都从 `https://www.1688.com/` 首页开始，因此类目入口连续失败时会表现为间隔刷新首页。
- Windows 服务检查时计划任务已退出、`8765` 无监听，任务摘要仍停留在 `running`；日志同时出现 `web_tasks.json.tmp -> web_tasks.json` 的 Windows 短暂拒绝访问。
- 未主动运行新的真实 1688 采集或制造安全验证场景。

## 根因

### 类目菜单没有展开

上次为解决 `locator.hover()` 自动滚动整个网页的问题，把类目 hover/click 改成了页面脚本派发 `PointerEvent/MouseEvent`。这些事件不是浏览器真实输入事件，1688 当前首页类目菜单没有据此展开二、三级菜单。

旧回归只断言“不能再使用 `scrollIntoView`”，没有同时证明“替代方案仍产生真实鼠标交互”，属于只覆盖副作用、没有覆盖核心能力。

### 多类目形成刷新循环

每个类目独立启动 RPA 是为了隔离结果，但零成功时仍会依次尝试全部类目。类目菜单属于所有子任务共享的前置能力；当前置能力系统性失效时，继续执行只会反复重新打开首页。

### 任务摘要可能停留在运行中

Windows 对任务状态文件的原子替换发生了短暂 `PermissionError`。旧实现只打印错误，没有重试，服务退出后可能留下旧的 `running` 摘要。

## 修复

1. 类目节点仍只滚动最近的菜单容器，不使用 `scrollIntoView` 或 locator 自动滚页。
2. 使用 Playwright `page.mouse.move()` 产生真实指针移动，使用 `page.mouse.click()` 点击叶子入口。
3. 点击前确认目标有可见 bounding box 且位于视口内；不满足时失败并保留诊断，不滚动 body 猜位置。
4. 零成功结果下，连续 2 个类目都返回 `category_navigation_not_loaded` 时触发熔断，停止剩余类目并记录连续失败数、跳过类目数和诊断。
5. 已有成功商品时不触发该零结果熔断，继续遵守“部分成功仍导出”的规则。
6. Windows 任务状态原子替换增加唯一临时文件和最多 4 次短暂重试。
7. 工作台版本更新为 `2026.07.20-category-navigation-r5`。

## 负例回归

- 源码不得再用脚本合成 `PointerEvent` 作为类目 hover。
- 类目交互必须包含真实 `page.mouse.move/click`。
- 四类目全部模拟导航失败时，只允许尝试前两个；剩余两个必须被熔断跳过，不能继续刷新首页。
- Windows `os.replace` 前两次模拟 `PermissionError` 时，第三次必须写入成功。
- 一个类目成功、后续一个失败时仍保留成功结果并导出，原部分完成回归继续通过。
